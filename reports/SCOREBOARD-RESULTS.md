## Диагностика опубликованной версии

Проверено 9 октября 2026 на https://oskolfilm-ui.github.io/poker-lab/ в Chromium с включённой проверкой HTTPS. Публичная версия 0.2 соответствует `main` — `aef0afb3519f75f3dc2091b3ccf487897af288ab`; GitHub Pages deployment `6959841618` и workflow `37925427983` успешны. Открытый PR #3 с AdaptiveAI ещё не опубликован.

HTML загружает `/poker-lab/assets/index-CvObLBcX.js` и `index-CQbj9qdk.css`. JS содержит компонент `match-scoreboard`, `heroWins` и счётчики рук. В реальном DOM отображается **единственное** табло HERO 0 : 0 AI.

Воспроизведённая причина потери видимости — расположение обычного, незакреплённого блока значительно выше стола. При viewport 1440×900 исходные координаты табло: y=277.19, высота 121; начало стола y=596.19. После прокрутки к картам Hero координаты табло y=−524.81, нижний край −403.81: весь блок находится за пределами экрана. Это воспроизводимая проблема размещения; код счёта на проверенном публичном сайте опубликован и работает.

На действующем публичном сайте отдельно проверена логика счёта. В изолированном тестовом профиле подготовлены легальные незавершённые руки: Hero лимпует, AI ставит all-in, Hero нажимает **Call 198 в опубликованном интерфейсе**. Сам опубликованный движок выполняет showdown. С заданной колодой проверены победа Hero (400/0) и победа AI (0/400). Счёт последовательно стал 1 : 0 и 1 : 1, не увеличился при reload; счётчики завершённых рук стали 1 и 2, сессионные — по 1. Нажатие «Следующий матч» начинало 200/200. Тестовые данные находятся только в браузерном профиле проверяющего, не на сервере и не в пользовательской истории.

Не обнаружено ошибки начисления очков, требующей второго счётчика. Произвольную старую вкладку пользователя эта проверка не идентифицирует; в новой версии добавлена видимая версия/ревизия сборки для проверки конкретного деплоя.

## Изменение

Существующее табло вынесено в `MatchScoreboard`, перемещено непосредственно над игровым столом и закреплено при прокрутке в пределах игровой области. Данные по-прежнему поступают из той же транзакционной статистики IndexedDB. Единственное очко начисляется после завершённой руки с нулевым стеком проигравшего; журнал матчей, защита от повторного начисления, пауза и подтверждение сброса сохранены. Версия базы и механизм начисления не менялись.

Результаты Hero выводятся из существующих завершённых рук. Для руки i:

```
profitBB[i] = (Hero.finalStack[i] - Hero.initialStack[i]) / 2
bb100[n] = 100 * sum(profitBB[1..n]) / n
```

Начальный стек берётся из каждой конкретной руки, включая руки после предыдущих проигрышей и новые матчи. Итоговые стеки уже включают блайнды, коллы, выигрыши и возврат неколлированной ставки. Сумма банка или выплата победителю не подменяют чистый выигрыш. Сплит даёт нулевой результат при неизменном стеке. Выдача начальных 200/200 не создаёт доход.

Уникальные завершённые руки сортируются по времени завершения. Незавершённые исключены. Сессионный фильтр использует существующий `sessionId`; старые записи без контекста остаются в общей истории. Очередь завершённых рук, ожидающих IndexedDB, может уже отображаться на графике; существующее сообщение об ошибке сохранения и блокировка автоперехода продолжают действовать. После восстановления записи не дублируются. Сброс счёта матчей не влияет на историю и график.

График показывает накопленный **средний bb/100**, рядом — чистый результат в BB и число рук. Есть выбор периода, наведение и выбор точки клавиатурой. На больших историях отрисовка ограничена 1200 промежуточными точками и итоговой точкой; среднее и выбор каждой руки всегда вычисляются по всей выборке.

## Проверки

- Unit: чистый проигрыш блайнда, выигрыш с возвратом all-in, неравные начальные стеки, сплит через настоящий движок, новый матч, дедупликация, исключение незавершённых, исторические записи и фильтр сессии. Существующие тесты атомарности IndexedDB, обоих победителей, сброса и миграций сохранены.
- Chromium desktop/mobile: реальные Call против all-in для обоих победителей, ровно одно очко, результат 3 секунды, автоматический новый матч 200/200, reload, новая сессия/вкладка, отдельные счётчики, bb/100, единственное закреплённое табло. Две восстановленные записи с результатами −0.5 и +100 BB дают +99.5 BB и +4975 bb/100; выбор первой точки показывает −50 bb/100. Повтор записи не удваивает результат.
- `npm run test:production`: Chromium открывает только собранные файлы `dist/` с путём `/poker-lab/`, без Vite и без SPA fallback. Проверяются фактические JS/CSS/шрифты, пять уровней ИИ, раздача против ИИ, 400 фишек, оба победителя матчей, автопереход, IndexedDB, график, TXT с TRAINING ONLY и H2N4 UNVERIFIED, перезагрузка и экраны 320/390 px. Скриншоты сохраняются в `test-results/production/`.
- После ручного merge: `deploy` публикует Pages, затем `verify-published` выполняет тот же браузерный протокол **против публичного HTTPS URL** и сверяет `release.json` и SHA в интерфейсе с SHA опубликованного коммита. Скриншоты — артефакт `published-verification`. Старая версия без графика или другой SHA эту проверку не проходит.

Новая версия до ручного объединения PR не опубликована. Локальная проверка `dist/` не называется проверкой нового публичного деплоя. Изменения построены поверх PR #3; сначала требуется объединить #3, затем этот PR в `main`. Автоматическое слияние не включается. Стратегия AdaptiveAI, покерный движок, схема IndexedDB, история и TXT-экспорт этим дополнением не изменяются.
