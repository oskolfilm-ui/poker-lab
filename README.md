# POKER LAB

Браузерный тренажёр Heads-Up No-Limit Texas Hold’em: Hero против AdaptiveAI. Только тренировочные фишки, без реальных денег и подключения к покерным румам.

## Запуск

Нужен Node.js 22.12+ (также поддерживается 20.19+). Проверено на Node.js 24.

```bash
npm ci
npm run dev
```

Vite запускается на порту 5173. Откройте адрес, указанный в его выводе. Серверная часть, API-ключи и переменные окружения не нужны. Шрифты входят в сборку; приложение не запрашивает внешние сервисы во время игры.

### Облачный предпросмотр

Для «Предпросмотра веб-страницы» должен работать **живой сервер**: из `/workspace/poker-lab` выполните `npm run dev` и оставьте процесс запущенным. Сборка `dist/` и опубликованный снимок среды не сохраняют работающий процесс: после восстановления среды Vite нужно запустить снова.

В `vite.config.ts` dev- и preview-серверы слушают `0.0.0.0:5173`. `strictPort` предотвращает незаметный переход на 5174. В изолированной облачной среде `allowedHosts: true` позволяет прокси предпросмотра обращаться с динамическим именем хоста. Этот режим предназначен для разработки; публичное production-развёртывание должно обслуживать `dist/` отдельным сервером.

Если окно пустое, проверьте HTTP-ответ на 5173 и запросы `/poker-lab/src/main.tsx`, `/poker-lab/src/App.tsx`, `/poker-lab/src/styles.css` в Network. Проверка `npm run test:e2e -- --grep 'embedded cloud preview'` открывает приложение в Chromium внутри iframe через прокси с внешним Host, проверяет реальные модули, стили, стол и сохранение руки. Это проверка прокси-сценария, а не управление самой панелью предпросмотра Codex.

```bash
npm test            # Vitest: правила, оценка рук, ИИ, IndexedDB, экспорт
npm run test:e2e    # Playwright: desktop + mobile
npm run build      # TypeScript + production-сборка в dist/
npm run preview    # просмотр production-сборки
npm run test:production # сборка + реальные браузерные проверки dist/ на /poker-lab/
```

Для браузерных тестов используйте установленный Chromium (`/usr/bin/chromium` в облачной среде) или `npx playwright install chromium`. Другой системный путь можно передать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

## Открыть в обычной вкладке

Сервер внутри облачной среды не даёт публичную ссылку сам по себе. Адрес `localhost` в вашем браузере относится к **вашему компьютеру**, а не к машине Codex. Для обычной вкладки используйте локальный запуск на своём компьютере или публикацию статической сборки.

### На своём компьютере

Скопируйте исходники, установите Node.js и выполните в папке проекта:

```bash
npm ci
npm run build
npm run preview
```

Пока сервер работает, откройте `http://localhost:5173/poker-lab/` в обычной вкладке. Для разработки вместо последних двух команд можно выполнить `npm run dev`. Не открывайте `dist/index.html` двойным кликом через `file://`: браузеры ограничивают загрузку ES-модулей и хранение данных в этом режиме.

### Самый быстрый бесплатный хостинг: Netlify Drop

1. Для сайта в корне домена выполните `npm run build -- --base=/`. Стандартная сборка использует `/poker-lab/` для GitHub Pages.
2. Распакуйте архив. Нужна папка с `index.html`, `favicon.svg` и `assets/`; при самостоятельной сборке это `dist/`.
3. Войдите или зарегистрируйтесь на [Netlify Drop](https://app.netlify.com/drop) и перетащите **эту папку**, а не папку с исходниками.
4. После загрузки Netlify выдаст HTTPS-адрес вида `https://имя-сайта.netlify.app`. Откройте его в обычной вкладке. Для этого статического приложения достаточно бесплатного тарифа в пределах его лимитов.

Настройки API и переменные окружения не нужны. Готовый архив уже содержит JS, CSS, шрифты и иконку. Для обновления снова выполните `npm run build -- --base=/` и загрузите новый `dist/` в тот же сайт.

### GitHub Pages: автоматическая публикация

Workflow готов в `.github/workflows/pages.yml`. Он проверяет Pull Request: устанавливает зависимости, запускает игровые и браузерные тесты, собирает и проверяет production-версию в Chromium. После слияния в `main` он публикует `dist/` официальными GitHub Pages Actions. В Pull Request публикация не запускается.

1. Сохраните исходники этой версии в репозитории `oskolfilm-ui/poker-lab`, включая `.github/workflows/pages.yml`, `scripts/verify-production.mjs`, `src/`, `public/`, конфигурации и `package-lock.json`. `node_modules`, `dist` и результаты тестов коммитить не нужно.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. На GitHub Free Pages доступен для публичных репозиториев; для частных репозиториев проверьте доступность Pages в вашем тарифе. Менять видимость репозитория для Netlify Drop не требуется.
3. Добавьте изменения в `main`. Workflow запускается при push в `main`; также его можно запустить через **Actions → Publish POKER LAB to GitHub Pages → Run workflow** после появления workflow в основной ветке.
4. Дождитесь успешного задания `deploy`. Рабочую ссылку GitHub покажет в **Settings → Pages** и в окружении **github-pages**.
5. Для указанного репозитория стандартный адрес после публикации: **https://oskolfilm-ui.github.io/poker-lab/**. Это ожидаемый адрес; до успешного деплоя он не является подтверждённой рабочей ссылкой.

В Vite явно задано `base: '/poker-lab/'`, поэтому ресурсы загружаются из подпапки GitHub Pages. Для публикации в корне другого хостинга используйте `npm run build -- --base=/`. Навигация «Тренировка / История рук» не меняет URL, поэтому серверный SPA-redirect не нужен. Workflow публикует только `dist/`; сама подготовка workflow не делает Git push и не публикует сайт.

После публикации завершите раздачу, откройте историю, перезагрузите вкладку и экспортируйте TXT. Для независимой локальной проверки `npm run test:production` обслуживает готовые файлы без Vite и проверяет путь `/poker-lab/`, загрузку JS/CSS/шрифтов, раздачу с ИИ, сохранность 400 фишек, IndexedDB, экспорт и мобильную верстку. Скриншот: `test-results/production/github-pages.png`.

При переходе на новый домен история остаётся в старом браузерном origin и автоматически не переносится. Перед переходом экспортируйте её. Импорт старых TXT в приложение пока не реализован.

## Возможности

- Блайнды 1/2, стартовые стеки 200/200 (100 BB), последовательные раздачи с сохранением стеков.
- Button одновременно SB и ходит первым на префлопе. BB ходит первым после флопа. Позиции меняются после каждой раздачи.
- Fold, Check, Call, Bet, Raise, All-in; ввод размера, ползунок и ставки в долях банка. **Raise to — итоговая ставка на текущей улице**, а не количество добавляемых фишек.
- Минимальная ставка 2, минимальный рейз по размеру последнего полного повышения, короткие олл-ины, коллы неполным стеком, возврат неуравненных ставок.
- Три burn-карты, все улицы, автоматический runout при олл-ине, вскрытие и делёж банка. Комбинации оценивает `pokersolver`, включая кикеры и стрит A–5.
- В heads-up суммы вкладов уравниваются по эффективному стеку: излишек возвращается. Дополнительный банк без третьего участника не создаётся. Rake 0; фишки целочисленные.
- ИИ использует базовую смешанную стратегию, пот-оддсы и Monte Carlo против случайной неизвестной руки (100 выборок). Граница `DecisionView` исключает карты Hero и настоящую колоду. Это учебный бот, **не GTO-решатель и пока не обучающаяся модель**.
- Адаптивный интерфейс, история, поиск, фильтрация, просмотр линии раздачи и экспорт одной/всех рук.
- После сохранения результата он показывается 3 секунды, затем автоматически начинается следующая раздача. Стеки сохраняются, Button/SB/BB меняются.
- Проигрыш всего стека завершает матч и приносит одно очко победителю. Через 3 секунды начинается следующий матч со стеками 200/200; сессия продолжается.
- Постоянное табло HERO : AI, независимые счётчики «Всего раздач» и «Раздач в сессии», подтверждаемый сброс только счёта матчей.
- Крупные банк, ставки и оставшиеся стеки. Справа — улица, Pot Odds и сумма колла для игрока, который сейчас принимает решение. При коротком колле Pot Odds исключают возвращаемый излишек ставки.

## Автоигра, сессии и счёт

«Пауза автоигры» останавливает автоматический переход между раздачами. Начатую руку можно доиграть; ИИ продолжает делать свои ходы. Пауза сохраняется при перезагрузке этой вкладки. Можно продолжить вручную кнопкой «Следующая раздача» / «Следующий матч» или включить автоигру: результат снова показывается 3 секунды. В истории и при открытом окне подтверждения автопереход приостановлен.

Обычная победа в раздаче не приносит очко за матч. Матч завершается только после распределения банка, когда один игрок остался без фишек. Промежуточный all-in не завершает матч до ответа соперника и определения победителя. Новый автоматический матч сохраняет сессионный счётчик и сквозной номер руки.

Новая вкладка начинает новую игровую сессию. Перезагрузка текущей вкладки восстанавливает её сессию. Кнопка «Новая сессия» после подтверждения начинает со стеков 200/200 и обнуляет только сессионный счётчик; незавершённый матч не приносит очко. Общий счёт, всего раздач и история остаются. «Сбросить счёт матчей» требует отдельного подтверждения и сохраняет историю и оба счётчика раздач.

## Хранение

Завершённая рука, общий и сессионный счётчики и результат завершённого матча записываются **одной транзакцией IndexedDB** через Dexie. Уникальные ID руки и матча защищают от повторного учёта при перезагрузке, React StrictMode и одновременном сохранении. Сброс счёта оставляет журнал матчей, поэтому повторный показ старой победной руки не возвращает её очко. Изменения статистики синхронизируются между открытыми вкладками через Dexie liveQuery.

При обновлении базы с версии 1 на 2 существующие руки сохраняются и входят в «Всего раздач». Новый сессионный счётчик и счёт матчей начинаются с нуля: прежняя история не содержит ID матчей для надёжного восстановления общего счёта.

Текущая рука, ID сессии/матча, пауза и очередь ожидающих сохранения рук восстанавливаются из `sessionStorage` в той же вкладке. При отказе IndexedDB появляется сообщение и кнопка повтора, автопереход и ручной переход блокируются до успешного сохранения; доступные руки можно экспортировать. Счётчики обновляются после успешной транзакции. Повторное открытие базы после ошибки позволяет сохранить очередь без перезагрузки.

История привязана к браузеру и origin. Очистка данных сайта, смена порта/origin или использование другого браузера не переносит её. Экспортируйте TXT как резервную копию. После закрытия вкладки текущая незавершённая сессия не гарантируется; завершённые руки остаются в IndexedDB. Синхронизации между устройствами нет.

## Экспорт и Hand2Note 4

Экспорт — **неофициальный PokerStars-style TXT** с привычными секциями HOLE CARDS, FLOP, TURN, RIVER, SHOW DOWN и SUMMARY. В файле есть явное `TRAINING ONLY`, имя стола `POKER LAB TRAINING`, метка `[POKER LAB TRAINING]` в каждой руке, дата UTC, нулевой rake. Фишки не имеют денежной стоимости. Это не история реальных игр PokerStars.

Основной целевой трекер — **Hand2Note 4**. **Совместимость не подтверждена**: реальный импорт в H2N4 не выполнялся. Пометки о симуляции и формат без денежной валюты могут потребовать отдельного адаптера для парсера. Локальные тесты подтверждают содержимое и суммы TXT, а не принятие файла внешним трекером. Перед заявлением о совместимости нужен реальный импорт с проверкой позиций, всех действий, стеков, возвратов, выигрышей и сплитов.

## Структура

```text
src/game/engine.ts      # чистые переходы состояния, легальные действия, банки и улицы
src/game/cards.ts       # колода и адаптер pokersolver
src/game/ai.ts          # DecisionView и базовая стратегия
src/game/match.ts       # завершение матчей и переход к следующей руке
src/game/decision.ts    # Pot Odds с учётом возвратов
src/history/store.ts   # транзакции IndexedDB: руки, статистика, сессии и матчи
src/history/export.ts  # маркированный TXT и скачивание
src/hooks/useHistory.ts # автосохранение, живая статистика и повтор при ошибках
src/hooks/useAutoAdvance.ts # трёхсекундный переход и отмена таймеров
src/components/        # стол, карты, действия и история
src/App.tsx            # сессия и навигация
tests/unit/            # правила и данные, включая 700 случайных раздач
tests/e2e/             # браузерные сценарии на desktop/mobile
scripts/verify-production.mjs # проверка готовой сборки для бесплатного хостинга
.github/workflows/pages.yml # сборка, проверка и публикация GitHub Pages
```

Движок не импортирует React, DOM или IndexedDB. `applyAction` не изменяет входное состояние и отклоняет нелегальные действия. Для воспроизводимых проверок `startHand` принимает генератор случайных чисел или полную заранее упорядоченную колоду.

Тесты статистики проверяют миграцию старой базы, одновременные повторы, победы обоих игроков, откат транзакции и независимый сброс счёта. Браузерные сценарии используют управляемые часы для границы 2999/3000 мс, паузы, восстановления после ошибки IndexedDB, новых матчей/сессий и сохранения данных при перезагрузке. На desktop/mobile дополнительно проверяется отсутствие наложения общих карт на карты игроков.
